# DJOneHub iOS 配置与发布操作说明（供开发者/AI 助手执行）

> 目标：在开发者账号下完成签名、开启 VoIP Push（CallKit 后台来电推送）所需的能力与证书，最终构建并提交 App Store 审核。

## 一、项目现状（已就绪，无需改动）

| 项目 | 状态 |
|---|---|
| Bundle ID | `com.djonehub.remote`（已固定，改动需同步全链路） |
| 版本 | 3.0（CFBundleShortVersionString=3.0，Build=27） |
| 后台模式 | Info.plist 已含 `audio` / `voip` / `fetch` |
| CallKit | 已实现 CXProvider 来电/去电上报、静音、挂断、DTMF |
| PushKit | 已实现 PKPushRegistry 注册、token 获取、上报给推送中继 |
| 推送中继 | App 设置页可填 `pushRelayURL`（Cloudflare Worker 地址），App 启动后自动向 `/v1/devices/register` 上报 voip_token |
| 联系人 | 本地 Contacts 框架读取（不上传服务器） |
| 演示模式 | UserDefaults `demoMode=true` 时走本地模拟数据，不连真实服务 |

**当前缺失、需在开发者账号侧补齐的**：VoIP Push 能力（entitlements）、VoIP Services 证书、后台推送所需的 provisioning profile。

## 二、开发者账号侧配置（按顺序执行）

### 1. 选择 Team 并确认签名
- Xcode 打开 `DJOneHub.xcodeproj` → Target `DJOneHub` → Signing & Capabilities
- Team 选**你的开发者账号**；Xcode 自动签名开启
- 确认 Bundle ID 为 `com.djonehub.remote`（如果账号下没注册过，Xcode 会自动创建；如冲突则先到 developer.apple.com 手动注册）

### 2. 添加 VoIP Push 能力（关键步骤）
- 在 Signing & Capabilities 点 `+ Capability`，搜索并添加 **Push Notifications**（必须，VoIP 推送依赖）
- 添加 **Background Modes**（若 Xcode 未自动同步，手动勾选 `Voice over IP` 和 `Audio`）
- 检查生成的 entitlements 文件应包含：
  ```
  aps-environment
  ```
  （VoIP 推送用 aps-environment + PushKit，不需要单独的 voip entitlement 键）

### 3. 创建 VoIP Services 证书（Apple Developer 后台）
1. 登录 [developer.apple.com](https://developer.apple.com) → Certificates, Identifiers & Profiles
2. Certificates → `+` → 选 **VoIP Services Certificate**
3. 按提示生成 CSR（钥匙串访问 → 证书助理 → 从证书颁发机构请求证书），上传 CSR
4. 下载 `.cer`，双击导入钥匙串（登录 → 我的证书）
5. **用钥匙串导出 .p12**（右键证书 → 导出，设置密码）——此 p12 用于后续推送服务端签名 VoIP 推送

### 4. 确认 App ID 能力
- Identifiers → 找到 `com.djonehub.remote` → 确认已勾选 **Push Notifications**（若之前没开，编辑保存后需重新生成 profile）

### 5. Provisioning Profile
- 让 Xcode 自动管理即可（自动签名会在构建时生成含 Push 能力的 profile）
- 若手动管理：创建 Development / App Store 两个 profile，勾选 App ID 与证书，下载安装

### 6. 推送服务端（中继）对接
- App 会把 `voip_token` POST 到 `pushRelayURL/v1/devices/register`（Cloudflare Worker）
- Worker 需要拿到 **第 3 步的 .p12** 用于向 APNs 发送 VoIP push：
  - 推送地址：`api.push.apple.com:443`（生产）/ `api.sandbox.push.apple.com:443`（开发）
  - topic：`com.djonehub.remote`
  - push type：`voip`
  - 若 Worker 已有实现，仅需更新 .p12 与 topic

## 三、本地验证（真机）

1. 连接 iPhone → 选真机作为 Run destination → Run
2. 首次运行会请求通知权限（PushKit 无需用户授权，VoIP 推送可直接到达）
3. 验证 PushKit token 是否打印到控制台（`[PushKit] voip token: xxx`）并成功上报 relay
4. 测试来电：App 退到后台/杀掉后，从服务端触发一次 VoIP push，观察 CallKit 来电界面是否弹出

## 四、提交 App Store 审核

### 1. Archive
- 真机选择下：Product → Archive（Release 配置）
- Organizer 里点 **Distribute App** → App Store Connect

### 2. 审核前必做（对照过往被拒点）
- **演示模式**：确保提交的版本 `demoMode` 关闭时也能让审核员体验；若需演示数据，在审核说明中写明"无账号模式即可使用演示功能"
- **隐私**：App 使用 Contacts 仅为本地展示，不采集不上传；在 App Store Connect 隐私标签中如实填写
- **后台推送说明**：在审核备注中说明 VoIP 推送用途（来电提醒，符合 CallKit 规范）
- **Review Notes**：提供演示账号/演示模式开启方法（如 `设置 → 演示模式`），以及恢复步骤（重启 App）

### 3. 提交
- App Store Connect 新建版本 3.0 → 上传构建（Xcode Organizer 或 Transporter）
- 填写隐私政策 URL（如无网站，可用 GitHub 仓库 README 链接）
- 提交审核

## 五、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 构建报 "no profiles found for com.djonehub.remote" | profile 未含 Push 能力 | 确认 App ID 已勾 Push Notifications 后重新生成 profile |
| PushKit token 为空 | VoIP 证书/能力未配 | 确认 Capability 加了 Push Notifications、profile 含 aps-environment |
| 后台被杀后来电不弹窗 | 推送未达或中继未配 | 确认 .p12 生产证书、topic、push type=voip |
| 审核被拒 5.2.5（外设） | 外接模块类 App 需说明用途 | 审核备注写清：本 App 配合大疆 4G 通信模块使用，需模块硬件支持 |

## 六、给 AI 助手的执行提示

- 全程只改 **签名/能力/证书**，不要动业务代码；业务逻辑已实现且稳定
- 所有证书/profile 操作以 Apple Developer 后台实际项为准，截图核对
- 构建报错先看报错段再动手，不要盲目重建
- 最终交付物：签名正确的 `.ipa`（或 App Store Connect 构建号）+ 审核说明草稿
